Resources

A Resource represents a piece of Terraform-managed infrastructure within an application. Resources are deployed asynchronously and their status is tracked by the platform.

Properties

FieldDescription
typeResource type matching a recipe in the environment
recipeRecipe name to use for provisioning
parametersOverride default recipe parameters
connectionsReferences to other resource outputs

Built-in Resource Types

Ryobi ships with predefined recipes for these resource types:

Resource TypeRecipeDescription
Ryobi.Compute/containerskubernetes-podKubernetes Deployment with replicas, ports, env vars, resource limits
Ryobi.Compute/virtualMachineskubevirt-vmKubeVirt VM with boot disk, cloud-init, networking, service exposure

Custom resource types can be created by writing Terraform modules and registering them as recipes.

Status

Resources track their provisioning state: Pending → Deploying → Succeeded or Failed. When a deployment fails, the error message is stored in the resource status. Outputs from Terraform are stored in the resource status on success.
