Environments

An Environment is a live agent that connects to the Ryobi server. It defines which cloud providers are available, what recipes can be used, and executes Terraform operations locally.

How Environments Work

Unlike static configuration, environments are managed by the ryobi-env agent binary:

  1. Start the agent with a config file: ryobi-env config.yaml
  2. The agent registers the environment with ryobid via gRPC
  3. It watches for resource events and executes Terraform locally
  4. On shutdown (Ctrl+C or SIGTERM), it unregisters and removes the environment

Key Properties

  • Providers — Cloud provider scopes (Azure, AWS, Kubernetes)
  • Terraform Providers — Provider blocks injected into generated Terraform configs (e.g., kubeconfig path)
  • Recipes — Terraform modules available for this environment

Configuration Example

# env-kubernetes.yaml (ryobi-env config)
name: dev
server:
  grpcAddress: localhost:9001
providers:
  kubernetes:
    scope: default
terraformProviders:
  kubernetes:
    config_path: "~/.kube/config"
recipes:
  - resourceType: Ryobi.Compute/containers
    recipeName: kubernetes
    templatePath: ../recipes/kubernetes-pod
    default:
      templateKind: terraform
      templatePath: ghcr.io/myorg/recipes/postgres:1.0
