YAML Schema

Reference for Ryobi application and environment YAML definitions.

Environment

An Environment defines the deployment target, cloud providers, and available recipes.

apiVersion: ryobi/v1        # Required. Must be "ryobi/v1"
kind: Environment            # Required. Must be "Environment"
metadata:
  name: <string>            # Required. Environment name

providers:                   # Optional. Cloud provider scopes
  azure:
    scope: <string>         # Azure scope (subscription + resource group)
  aws:
    scope: <string>         # AWS scope (account + region)
  kubernetes:
    scope: <string>         # Kubernetes scope (namespace)

recipes:                     # Optional. Recipe registry
  <resourceType>:           # e.g. "Ryobi.Compute/containers"
    <recipeName>:           # e.g. "kubernetes"
      templateKind: terraform  # Required. Must be "terraform"
      templatePath: <string>  # Required. Terraform module source (local, registry, git)
      parameters:              # Optional. Default parameters
        <key>: <value>

recipeConfig:                # Optional. Global recipe configuration
  terraform:
    providers:               # Provider-level configuration
      azurerm:               # Azure provider
        subscription_id: <string>
      aws:                   # AWS provider
        region: <string>
      kubernetes:            # Kubernetes provider
        config_path: <string>  # e.g. "~/.kube/config"

Application

An Application groups resources that are deployed together. The environment can be specified explicitly or determined automatically by the placement engine.

apiVersion: ryobi/v1        # Required. Must be "ryobi/v1"
kind: Application            # Required. Must be "Application"
metadata:
  name: <string>            # Required. Application name
  environment: <string>     # Optional. Target environment (placement decides if omitted)

resources:                   # Optional. Resources to deploy
  - name: <string>          # Required. Resource name
    type: <string>          # Required. Resource type
    recipe: <string>        # Optional. Recipe name (placement selects if omitted)
    parameters:              # Optional. Parameter overrides
      <key>: <value>
    connections:             # Optional. References to other resources
      - name: <string>      # Connection name
        source: <string>    # Source resource name
        key: <string>       # Output key to inject
    placement:               # Optional. Placement policy (used when environment/recipe omitted)
      constraints:           # Hard requirements — environment must match all
        region: <string>    # e.g. "eu-west-1"
        sovereignty: <string>  # e.g. "eu"
        capabilities:        # e.g. ["gpu", "high-memory"]
          - <string>
      preferences:           # Soft scoring — ranks matching environments
        cost: minimize       # Prefer cheapest environment
        availableResources: maximize  # Prefer most free capacity

Multi-Document Files

You can combine environments and applications in a single file using YAML document separators (---). Environments are always processed first.

apiVersion: ryobi/v1
kind: Environment
metadata:
  name: dev
recipes:
  Applications.Datastores/postgresDatabases:
    default:
      templateKind: terraform
      templatePath: ghcr.io/myorg/recipes/postgres:1.0
---
apiVersion: ryobi/v1
kind: Application
metadata:
  name: my-app
  environment: dev
resources:
  - name: database
    type: Applications.Datastores/postgresDatabases
    recipe: default

FieldTypeRequiredDescription
apiVersionstringYesMust be ryobi/v1
kindstringYesApplication or Environment
metadata.namestringYesUnique resource name
metadata.environmentstringNoTarget environment (placement decides if omitted)
resources[].namestringYesResource name within the app
resources[].typestringYesResource type matching recipe registry
resources[].recipestringNoRecipe name (placement selects if omitted)
resources[].parametersmapNoOverride recipe default parameters
resources[].connectionslistNoReferences to other resource outputs
resources[].placementobjectNoPlacement policy for automatic environment selection
resources[].placement.constraints.regionstringNoRequired region (must match)
resources[].placement.constraints.sovereigntystringNoRequired sovereignty zone (must match)
resources[].placement.constraints.capabilitieslistNoRequired capabilities (all must match)
resources[].placement.preferences.coststringNominimize — prefer cheapest environment
resources[].placement.preferences.availableResourcesstringNomaximize — prefer most free capacity
